## 1. 动效结论

新动效不再以“像素块散开 / 聚合”为核心，而以**字符密度场的生成、迁移、扰动和稳定**为核心。每个动效都必须回答四件事：

1. 什么触发？
2. 哪个状态改变？
3. 用户通过什么视觉结果理解改变？
4. 结束后是否回到安静、清晰、可操作的页面？

用户提出的 Claude Fable“最高功率启动紫色蔓延”被作为**行为参考**，不是照搬品牌资产。已定位到 [Claude Fable 官方页面](https://www.anthropic.com/claude/fable)、[官方发布文](https://www.anthropic.com/news/claude-fable-5-mythos-5)与[官方发布视频](https://www.youtube.com/watch?v=CIQBP1w4B1M)，但官方没有公开组件名、源码或算法；精确节奏仍需用户提供对应片段或时间码。当前方案只采用已确认的行为结构：局部种子、不规则前沿、全场唤醒、尾迹沉降。

| 动效 | 触发 | 结果 | 强度 | 时长 / 帧率 | 降级 |
|---|---|---|---|---|---|

## 3. 高功率字符蔓延

### 3.1 触发

首轮实验同时提供两个开关：

- `AUTO ONCE`：页面资源可用后自动播放一次，不阻塞内容出现。
- `CTA TRIGGER`：点击“查看核心项目”时从按钮位置起始。

正式网站只保留一种。招聘场景优先推荐 `CTA TRIGGER`：用户先读到职业定位，再用主动操作启动最强事件，因果更清楚，也避免每次刷新都看启动片。

### 3.2 视觉结果

1. 起点先出现一小团低饱和紫色稀疏字符。
2. 不规则前沿向外扩散，不是完美圆形，也不是线性矩形 wipe。
3. 前沿经过的单元依次走过 `空白 → .:- → =+* → #@`。
4. 紫色只存在于前沿与少量尾迹，最终稳定为暖琥珀 / 青灰主终端色。
5. 内容 DOM 从始至终可读；蔓延层只在背景或受控窗口中运行。

### 3.3 强度与节奏

- 扩散主段：约 760ms。
- 尾迹稳定：约 240ms。
- 前 15% 时间快速建立能量，中段不匀速，最后 25% 明显减速。
- 使用 `cubic-bezier(0.22, 1, 0.36, 1)` 作为总体包络；字符前沿内部用噪声偏移，不给每个字单独创建 DOM 动画。

## 4. 章节 ASCII 填充

### 4.1 触发

当章节标题中心进入视口 45%–60% 区间时启动；反向滚动离开后不立刻清空，只有当前章节变化时才把上一条降为稀疏稳定态。

### 4.2 视觉结果

- 当前栏目：`....::::----====++++****####@@@@`
- 已读栏目：保留约 25% 密度的短字符线。
- 未读栏目：只显示编号与极弱定位点。

它必须与导航当前状态使用同一 section id，修复“标题、内容、导航各自表达不同当前位置”的问题。

### 4.3 强度

- 只占标题区域 8–16px 高度。
- 不覆盖标题文字，不延伸成大面积装饰。
- 每个章节只在首次进入时完成一次明显填充，之后只做低强度状态切换。

## 5. 鼠标字符场

### 5.1 触发范围

- 仅 `hover: hover` 且 `pointer: fine`。
- 只在 Hero 大留白、章节之间的受控背景和 ASCII 实验窗口中启用。
- 卡片正文、视频控件、链接和按钮区域不响应背景字符，避免抢焦点。

### 5.2 推荐模式

首轮原型并排比较三种模式：

1. `LUMINANCE`（推荐）：半径内字符沿坡度变密 / 变亮，最克制。
2. `FLOW`：字符方向符号 `/\\|_` 随鼠标速度旋转，技术感更强。
3. `REPEL`：字符位置轻微外推，视觉最显眼，也最容易像粒子特效。

正式网站预计保留 `LUMINANCE`，最多混入 15% 的 `FLOW`；不推荐把 `REPEL` 作为常驻背景。

### 5.3 参数

- 影响半径：桌面 140–180px。
- 单字符位移：最多 0–2px；以字符替换和亮度变化为主。
- 跟随延迟：40–70ms。
- 离开回落：180–240ms ease-out。
- 更新上限：30 FPS；鼠标静止 120ms 后停止绘制。

## 6. GAME WORK 媒体安全的 ASCII 外围联动

### 6.1 触发

沿用当前已验收的项目滚动 / 键盘切换关系，不扩大 hover 感应范围。只有 active project 真正变化时启动外围字符信号。

### 6.2 联动算法

1. 旧 / 新真实媒体在原媒体层直接交接，不经过字符采样、Dither 或 ASCII 滤镜。
2. active project 改变时，在共享窗口边框或状态轨产生一个字符能量种子。
3. 带方向噪声的前沿沿外围字符场传播，同步更新项目编号、状态和技术栈。
4. 传播期间媒体保持清晰；字符不得横穿封面主体或遮挡视频控制。
5. 媒体稳定后 120–220ms 内，外围字符从高密度退回低对比完成态。

任何时刻都不得出现整帧黑场。快速连续切换时，中断当前外围时间线并从当前可见状态接管，不排队播放。

### 6.3 强度

- 媒体主体始终比控制框更重要，并且永远保持原始画面。
- 字符层只存在于共享媒体窗口外围、状态轨和邻近空白，不覆盖媒体内容。
- 控制层同步更新项目编号、状态和技术栈，但不增加伪造日志。

## 7. 动效前后变化表

| 现状 / 被否决方案 | 新方向 | 原因 |
|---|---|---|
| 静态 48×6 像素材质带 | 章节 ASCII 密度填充 | 有触发、进度和稳定状态，能解释当前位置 |
| 规则方格组成的低分辨率装饰 | 字符坡度组成的明暗与边缘 | ASCII 的媒介本体是字形，不是方块 |
| GAME WORK Bayer 像素交接 | 真实媒体干净交接 + 外围 ASCII 信号 | 保留无黑帧优点，同时不把作品素材字符化 |
| 普通 hover 变色 | 局部字符亮度 / 方向响应 | 交互反馈与全站语言一致 |
| 全屏持续 CRT 故障 | 稀有高功率蔓延 + 安静稳定态 | 强事件更值得记忆，正文更易读 |

## 8. 技术与性能边界

- 第一原型使用 Canvas 2D 自建字符采样器，复用当前 React / Canvas 架构，不立即安装大型图形依赖。
- 字符画不是每个字一个 React 节点；单个 Canvas 批量绘制，避免布局抖动。
- 只在状态改变、鼠标移动或项目切换时绘制；静止后停止循环。
- 桌面最多 120×68 字符格，手机最多 64×72；最终参数以真实设备测量为准。
- 背景交互不读取整页截图或作品媒体，只处理程序生成的网站字符场。
- `prefers-reduced-motion: reduce` 下关闭传播、鼠标跟随与持续漂移，保留静态 ASCII 完成态。
- 页面隐藏时暂停 Canvas；离开区块时取消动画帧与事件监听。

[textmode.js](https://github.com/humanbydefinition/textmode.js)证明了 WebGL2、实例化网格、字体加载和动态图层能够实现高性能实时 textmode；[Three.js AsciiEffect](https://threejs.org/docs/pages/AsciiEffect.html)也提供标准字符集与分辨率控制。但本项目第一轮不依赖它们：当前需求是 2D 网站字符场与外围状态联动，Canvas 2D 更容易控制、降级和接入。若实验页在中端设备达不到目标，再评估 textmode.js。

Reddit 对 [Ghostty ASCII 动画的拆解](https://www.reddit.com/r/webdev/comments/1hn9e20/)提供了一个有用事实：逐帧更新字符内容或把预制帧转成 ASCII 都可行；但作品集不能为了效果持续重绘全文。本项目采用字符密度映射与局部 Canvas，而不是把整个页面变成不断更新的 `<code>` 文本。

## 9. 验收标准

- 用户第一眼能说出“这是字符构成的终端画面”，而不是“像素块 / Dither”。
- 高功率蔓延有清楚起点、前沿、尾迹和完成态，不是普通紫色渐变 wipe。
- 鼠标交互只影响局部字符场，不改变链接感应范围，不造成漂移感。
- GAME WORK 切换中无硬黑帧，真实媒体全程保持原貌，ASCII 只在外围反馈状态。
- 手机、键盘和 Reduced Motion 不依赖动效理解内容。
- 没有常驻高负载全屏循环。

# Phase 4 首页支持内容设计

## 目标

Phase 4 补充证明朱翊嘉在游戏原型、实时视觉和工具系统方面的能力，但不能削弱两个 Selected Games 的主视觉权重。支持内容应当像一组可浏览的研究档案，而不是第三、第四组大型项目卡片。

## 方案取舍

### 方案 A：继续使用大型项目叙事

每个支持项目延续 Selected Games 的大标题与大画面。优点是表现力强；缺点是六个次级项目会显著拉长首页，并让访客难以判断重点。

### 方案 B：紧凑档案带（采用）

Gameplay Lab 使用三列实验条目，Worlds 使用一主一次的非对称构图，Tools 使用单一横向入口。所有区域共享编号、信息轨道与中文排版规则，但字号、媒体面积和动效幅度低于 Selected Games。

### 方案 C：交互式能力仪表盘

通过筛选、标签和浮动预览切换所有项目。优点是信息密度高；缺点是需要更多状态、动画和学习成本，容易产生工具网站感，不符合当前作品集的编辑式叙事。

## 公开边界

### Gameplay Lab

展示统一数据源中属于 `gameplay-lab` 的三个个人实验：

- IK 重定向
- 迭代缩小
- 跟随指针

每项显示中文名称、简短说明、技术标签和按需视频。视频在用户点击后才加载；切换实验时卸载上一段视频。

### Worlds & Visual Systems

展示已确认的 StoneCity《石之城》和 Tajima Cutter 美工刀。

- StoneCity 作为主要视觉项目，使用现有短视频，首页文案缩短为能力说明。
- Tajima 只使用现有 Sketchfab 最终模型，不把纹理通道冒充最终作品；3D iframe 在点击后加载。
- Peak 与 Blade Runner 的首页选择尚未确认，因此两者都不渲染。

### Tools & Interactive Systems

当前只展示 NewFace 节点式 AI 工作站，封面直接进入现有独立网页。

- Meshy.ai 的公开边界未确认，不渲染。
- 网页代表项目未选择，不自行挑选。

## 信息层级

首页章节编号调整为：

1. 精选游戏
2. 玩法实验室
3. 世界与视觉系统
4. 工具与交互系统
5. 关于与联系

支持区中文标题使用 `clamp(2.2rem, 4.2vw, 4.5rem)`，低于 Selected Games 的章节标题。项目名称使用 `clamp(1.4rem, 2.4vw, 2.5rem)`；正文保持 1.75 行高；中文标签使用 0.04em 字距，技术标签使用等宽字体。

## 交互规则

- 页面初始不加载支持区视频或 3D iframe。
- 用户点击媒体区域后加载并播放；同一时间只保留一个动态媒体。
- 再次点击当前媒体可关闭，恢复轻量占位界面。
- NewFace 使用普通链接直接打开现有项目网页。
- 鼠标悬停只改变边框、文字位置和遮罩；触屏保留清晰的播放按钮。
- `prefers-reduced-motion` 下取消位移和媒体缩放。
- 键盘用户可以聚焦、打开和关闭全部媒体。

## 响应式规则

- 桌面：Gameplay Lab 三列；Worlds 一主一次；Tools 横向入口。
- 平板：Gameplay Lab 保持三列但减小间距，Worlds 改为上下排列。
- 手机：所有支持项目单列；视频和 3D 使用 4:3 比例；操作按钮始终可见。

## 验收标准

- 首页出现 `#gameplay-lab`、`#worlds` 和 `#tools`。
- 三个 Gameplay Lab 项目、StoneCity、Tajima 与 NewFace 来自统一项目数据。
- Peak、Blade Runner、Meshy.ai 和未选定网页项目不出现在首页。
- 初始 HTML 不包含支持区视频或 iframe，避免抢占加载资源。
- 点击后同一时间最多渲染一个动态媒体。
- 两个原游戏网页与其目录保持不变。

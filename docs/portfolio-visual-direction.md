# 作品集视觉规范：Pixel Signal / 像素信号场

> 版本：Round 5 Visual Direction v2  
> 日期：2026-08-11  
> 状态：APPROVED BASELINE / WAITING FOR REVIEW  
> 当前范围：仅 GAME WORK / 核心游戏开发项目  
> 配套动效：portfolio-motion-design.md  
> 参考：用户提供的两张风格图、[Moonshot · Kimi 招聘站](https://careers.kimi.com/)、[tait-crt-interface-skill](https://github.com/TaiT-tt/tait-crt-interface-skill)

## 1. 设计结论

本项目采用 **Pixel Signal / 像素信号场** 作为 GAME WORK 的局部视觉语言：

- 用现代黑色编辑排版建立专业、克制的内容骨架。
- 用像素字体、12px 方格、6px 半格、硬边台阶和诊断栏建立识别度。
- 用酸性黄绿、苔藓绿、灰白形成受限色板与量化色阶。
- 用真实项目视频、封面和真实技术字段承担内容证明。
- 用一次短促像素拆散 / 聚合承担项目切换事件。
- 不设置与项目无关的常驻右侧像素主体。

最终观感应像一套正在运行的游戏开发展示系统，而不是复古系统复刻、8-bit 游戏菜单或 AI 生成海报展。

## 2. 视觉目标与优先级

视觉决策按以下顺序判断：

1. 招聘方能否在数秒内识别 UE / C++ 游戏开发定位。
2. 项目媒体与技术证据是否仍是视觉主角。
3. 三个核心项目的状态与入口是否清晰。
4. 像素语言是否统一、有节制、可被记住。
5. 装饰是否会妨碍阅读、播放、键盘操作或移动端浏览。

如风格表现与前四项发生冲突，优先保留内容、证据和入口。

## 4. 核心视觉原则

### 4.1 一个像素尺度

- 主像素单位为 12px。
- 6px 只用于半格边角、细状态块和小型校准标记。
- 24px、36px、48px 等尺寸优先由 12px 整数倍组成。
- 像素装饰的位置与尺寸应尽量落在整数坐标，避免半像素发虚。
- 同一组件内不得混用多套互不相关的像素密度。

### 4.2 真实媒体优先

- 项目视频、截图和封面保持清晰，不主动像素化。
- 像素化仅用于窗口边缘、切换遮罩、状态段与装饰层。
- CRT 扫描线不得盖过正文，也不得使项目画面失去细节。
- 项目媒体的视觉面积应明显大于诊断信息与装饰像素。

### 4.3 受限而非贫乏

- 单个稳定画面使用 2–5 个主色。
- 渐变通过离散色阶、抖动网点或像素密度表达。
- 不使用模糊玻璃、彩虹霓虹、柔软大阴影制造“高级感”。
- 留白是视觉系统的一部分，不用像素块填满所有空间。

### 4.4 工程感而非扮演感

- 诊断栏只展示真实字段：项目顺序、年份、角色、技术栈和项目状态。
- 不伪造 FPS、构建进度、代码量、内部性能结果或命令行输出。
- 界面可以像工具，但不能要求用户学习一套虚构操作系统。

## 5. 视觉令牌

### 5.1 色彩

| 令牌 | 值 | 职责 | 使用限制 |
|---|---|---|---|
| Void Black | #090A09 | GAME WORK 背景、窗口暗部 | 大面积使用 |
| Signal White | #F1F2ED | 标题、正文、关键边线 | 主文字色 |
| Acid Lime | #D8FF32 | 当前状态、像素信号、关键入口 | 单屏高亮面积应受控 |
| Moss Shadow | #48540F | 量化色阶暗部、非活动信号 | 不用于长正文 |
| Signal Gray | #777B74 | 次级文字、未激活状态 | 需保持可读对比 |
| Surface Black | #111310 | 媒体窗与诊断栏层次 | 与主背景保持微差 |

配色规则：

- Acid Lime 只表示“当前、可行动、切换事件”，不能成为普通装饰底色。
- Signal White 承担阅读，不能让所有文字都变成黄绿。
- Moss Shadow 与 Signal Gray 只作为层级过渡，不承载重要入口。
- 当前橙色不在 Round 5 内迁移或删除；全站强调色统一留到 Round 6 决定。

### 5.2 字体

GAME WORK 局部使用 Fusion Pixel 12px Proportional zh_hans，字体与许可证保存在 public/fonts/fusion-pixel。

| 文本角色 | 字体策略 | 建议尺寸 | 规则 |
|---|---|---:|---|
| 区块英文标题 | 像素字体 | 48–96px | 可大，但不压过项目媒体 |
| 项目中英短标题 | 像素字体 | 24–48px | 中英文可同系统混排 |
| 编号 / 状态 / 标签 | 像素字体 | 12–14px | 大写英文控制字距 |
| 按钮短文案 | 像素字体 | 12–16px | 必须保持可辨认 |
| 中文摘要 | 现有正文字体 | 16–20px | 不像素化长段落 |
| 技术说明 | 现有正文字体 | 14–18px | 阅读优先 |

排版规则：

- 优先使用 12 / 24 / 36 / 48 / 72 / 96px 的离散级别。
- 中文长标题使用 keep-all 与平衡换行；仍过长时降低一个字号级别。
- 手机项目标题不低于 24px，正文不低于 16px。
- 像素字体不得覆盖 Profile、经历长文和 Archive 大量项目说明。
- 英文像素字负责“界面语气”，中文正文负责“信息效率”。

### 5.3 间距与网格

基础间距序列：6 / 12 / 18 / 24 / 36 / 48 / 72 / 96px。

- 6px：半格细节、图标与文字微调。
- 12px：标签内距、像素边角、状态块。
- 24px：组件内部主要间距。
- 36–48px：项目条目内部层级。
- 72–96px：区块标题与核心内容分隔。
- 非必要时不引入 7px、13px、29px 等游离值。

## 6. 表面、边框与层级

### 6.1 窗口层级

| 层级 | 元素 | 表现 |
|---|---|---|
| L0 | GAME WORK 舞台 | 连续黑色背景与大留白 |
| L1 | Runtime Signal Viewport | 主要硬边窗口，承载真实媒体 |
| L2 | 诊断栏 / 状态段 | 薄边、低对比底色、小字号 |
| L3 | 像素信号 | 短时出现，完成后必须退场 |
| L4 | 交互高亮 | Acid Lime 边线、文字或小块，不遮挡内容 |

### 6.2 边框规则

- 主窗口使用 1px 清晰边线，并以 6px / 12px 台阶角建立像素特征。
- 不使用大圆角；小型控制也不依赖胶囊按钮。
- 棋盘格只用于状态段或边角校准，不铺成大面积背景。
- 阴影若存在，只能极弱且不模糊像素轮廓。

### 6.3 CRT 表面

- 扫描线与网点限制在媒体窗口内部。
- 静态不透明度建议 4–7%，验收以“不妨碍项目细节”为准。
- 不做全页扫描线、持续故障、色散漂移、亮度闪烁或桶形呼吸。
- Reduced motion 不需要移除纯静态纹理；若影响可读性则直接移除。

## 7. 组件映射

| 组件 | 必须体现的像素语言 | 应保持现代简洁的部分 |
|---|---|---|
| GAME WORK 标题 | 像素字体、编号、短状态词 | 大留白、清晰层级 |
| Runtime Signal Viewport | 台阶角、薄边、静态扫描线、短时像素信号 | 16:9 真实媒体、播放与入口 |
| 项目条目 | 像素编号、当前边线、技术标签 | 中文摘要、项目入口 |
| 诊断栏 | 12px 网格、灰白与黄绿状态 | 只显示真实字段 |
| 01 / 02 / 03 状态段 | 棋盘式离散状态、aria-current | 不伪装成加载进度 |
| 项目按钮 | 硬边、短文案、清晰焦点 | 44px 以上可触目标 |
| 平板 / 手机项目 | 局部台阶角、静态像素边框 | 纵向媒体与正文，不共享粘滞窗口 |

- Hero
- Systems Lab
- Industry Experience
- Relevant Work
- Archive
- Profile
- Contact
- 全站导航

## 8. Runtime Signal Viewport 的视觉状态

### 稳定状态

- 当前项目媒体清晰、占主导。
- 像素信号层完全隐藏。
- 当前项目编号和必要标签使用 Acid Lime。
- 其他项目保持可读但降低对比。
- 诊断栏只显示当前项目的真实字段。

### 切换状态

- 旧媒体轻微降低可见度，不做长时间模糊。
- 有限数量的方形像素从既定位置短暂拆散并重新聚合。
- 新媒体在同一窗口内恢复清晰。
- 560ms 后所有装饰像素退场，稳定状态重新成立。

### 预留项目状态

- Upcoming UE / C++ Project 没有真实媒体时显示诚实的保留窗口。
- 可显示 BUILD TARGET RESERVED、Unreal Engine、C++ 与项目顺序。
- 不生成假截图、假代码或虚构完成百分比。

## 9. 媒体与资产处理

- 视频与封面优先读取 Asset Pipeline 的统一派生文件。
- 项目媒体使用 object-fit 与用户确认的裁切参数；不能为了像素风再次裁切。
- 像素位图资产才允许 image-rendering: pixelated；真实 3D、游戏截图和视频保持正常采样。
- Poster 与视频切换不能造成布局跳动。
- 媒体窗口必须有明确背景色，资源加载失败时仍保留标题、说明和入口。

## 10. 响应式规则

### 桌面：1100px 及以上

- 启用共享 Runtime Signal Viewport 与 65 / 35 主次布局。
- 主媒体短距离 sticky，项目条目正常滚动。
- 启用完整 560ms 像素切换。

### 平板：721–1099px

- 改为每个项目自己的纵向媒体与内容。
- 不共享 sticky 主窗口。
- 最多保留一次 240–300ms 的局部像素边缘反馈。

### 手机：720px 及以下

- 使用完全纵向结构。
- 不依赖 hover，不锁屏，不共享媒体层。
- 保留像素字体、台阶角与静态状态标记。
- 动态像素层默认不启用，确保浏览速度。

### Reduced motion

- 立即显示当前内容，不使用位移、缩放、渐变或像素拆散。
- 所有项目事实、媒体、按钮和入口保持完整。
- 静态像素排版可以保留，但不能用闪烁表达状态。

## 11. 风格密度上限

一个桌面稳定画面建议同时出现：

- 1 个主媒体窗口。
- 1 个低高度诊断栏。
- 1 组 01 / 02 / 03 状态段。
- 不超过 2 处 Acid Lime 主要高亮。
- 0 个与项目无关的常驻像素主体。
- 0 个持续循环的装饰动画。

如果新增元素使项目标题、媒体或入口退居次要，应删除该元素。

## 12. 明确不采用

- 全站 Windows 95、Mac OS、Minitel 或复古游戏 HUD 复刻。
- 与项目无关的右侧像素球体、月球、人物或 AI 物体。
- 大量浮动小窗、假终端、假构建日志和假数据图。
- 全页持续扫描线、闪烁、故障、色散与桶形扭曲。
- 长正文像素字体。
- 每个区块重复同一种像素溶解。
- 全屏 Canvas / WebGL 作品集壳层。
- 自定义鼠标拖尾、隐藏式导航或需要猜测的交互。
- 为风格改变项目事实、媒体、入口和技术定位。

## 13. Round 5 验收清单

- [ ] 黑、酸性黄绿与灰白形成清晰层级，黄绿没有泛滥。
- [ ] 真实项目媒体仍是最大、最清晰的视觉证据。
- [ ] 中英文像素标题可读，中文正文未被像素化。
- [ ] 台阶角、12px 网格、状态段和诊断栏属于同一语言。
- [ ] 右侧没有常驻的无关像素主体。
- [ ] 项目切换结束后像素层完全退场。
- [ ] 1100px、1024px 与手机结构各自完整，无横向溢出。
- [ ] 键盘焦点、Reduced motion 与触屏不依赖视觉特效才能使用。
- [ ] 其他七个区块未被提前迁移到新视觉系统。

## 14. 后续扩展门槛

Round 5 通过后，Round 6 也不默认全站像素化。任何扩展必须同时满足：

1. 能解释内容层级或当前状态。
2. 与 12px 网格、受限色板和硬边规则一致。
3. 不复制 GAME WORK 的核心 560ms 转场。
4. 在触屏、键盘和 Reduced motion 下有等价信息。
5. 不增加新的常驻视觉主体。

优先考虑把像素语言轻量扩展到导航当前状态或区块编号；不优先扩展到正文、履历和完整 Archive 列表。

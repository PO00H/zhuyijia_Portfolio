## 1. 方向修正

Round 8D 的静态像素材质已被否决并回退。问题不只是“画得不好看”，而是媒介选错：

- 方格、低分辨率色块和 Bayer 抖动仍然属于像素 / Dither 语言。
- 用户需要的是**字符本身构成明暗、边缘、体积和运动**的 ASCII / Textmode 语言。
- 静态装饰带没有触发、状态变化和反馈，不构成交互。
- 规则方格让页面继续像现代矢量终端，只是贴了一层像素纹理。

因此，本文件不再把“12px 方格、像素色阶、静态像素材质”作为全站视觉规范。已验收的信息结构、中文内容、真实项目媒体和清晰入口继续保留。

## 2. 新视觉结论

网站应像一套**低饱和、正在运行的字符终端作品档案**：

1. 现代、克制的内容排版负责可读性和招聘效率。
2. ASCII 字符网格负责网站背景、状态、边界与转场，不用方块假扮字符。
3. 真实项目视频和截图始终保持原貌并作为证据主体；ASCII 只作用于网站界面、空白区域和交互反馈。
4. 终端感来自等宽字符、字符密度、有限色阶、轻扫描线与响应式状态，不来自伪命令行文案。
5. 鱼眼、四角阴影和更强 CRT 质感属于第二轮外壳调校，不在第一轮遮盖正文或项目媒体。

## 3. 参考图的有效特征

用户本轮四张参考图共同强调：

- 轮廓由字符密度而不是连续曲线组成。
- 同一个字符网格同时承载大形体、阴影、背景噪声和局部高光。
- 色彩像老式显示器的磷光染色：暗、旧、低饱和，不是现代霓虹渐变。
- 字符在近距离可读为符号，远距离合成为图像。
- 扫描线、轻微亮度漂移、边缘暗角只增强材质，不代替主体。

[ASCII Magic 的字符指南](https://www.ascii-magic.com/blog/ascii-characters-full-guide)说明了正确的基础：先把画面划分成字符单元，计算每格亮度，再从稀疏到密集的字符坡度中选字；字符坡度与网格尺寸是最关键的两个变量。它也明确区分了 Characters 与 Pixel Art，因此本方向使用字符，不使用色块作为主语言。

## 4. 色彩候选，不是最终锁色

参考图提供的是色彩气质，不要求复制任意一张的色值。第一版实验使用三套低饱和终端候选：

| 方案 | 背景 | 主磷光 | 高亮 | 事件色 | 用途 |
|---|---|---|---|---|---|
| A 暖琥珀（推荐） | `#0b0907` | `#a9844f` | `#d5b77f` | `#77658f` 低饱和紫 | 全站基础与 Claude 式“功率蔓延”事件 |
| B 冷青灰 | `#07100f` | `#5f8781` | `#9bb8b0` | `#a77a55` 旧铜色 | 系统实验、诊断内容 |
| C 灰紫 | `#0d0a10` | `#796a8d` | `#b2a3bf` | `#a78658` 暖金 | 更艺术化的备用方向 |

推荐先验证 A：它与当前酸性黄绿和 Meshy 风格拉开距离，同时保留一个很克制的低饱和紫色，只在高功率启动、主项目切换等少数事件中出现。

禁止：

- 大面积纯黑 + 高饱和荧光绿。
- 多彩赛博霓虹、彩虹色差和持续 RGB 抖动。
- 用渐变背景冒充 CRT 磷光。
- 在没有状态变化时持续闪烁或发光。

## 5. 字符系统

### 5.1 字符坡度

- 网站字符场明暗：` .,:;i1tfLCG08@`
- 章节进度与状态：` .:-=+*#%@`
- 边缘强调：`/\\|_()[]<>`
- 不把 `█▓▒░` 作为默认坡度；它更接近 Block Characters / 像素块，只在小范围校准条中测试。

坡度必须先按当前字体的实际墨量排序，不能假定每个字体中的 `@`、`#`、`.` 密度完全一致。

### 5.2 网格密度

- 桌面背景实验：80–120 列。
- GAME WORK 外围状态场：56–96 列起测，不覆盖媒体画面。
- 手机：40–64 列，禁止直接缩放桌面字符场。
- 网格必须由字体测量结果计算，不能只用 CSS `letter-spacing` 硬凑。

### 5.3 字体职责

- ASCII 画面、英文状态字、编号：稳定的等宽终端字体。
- 中文正文、项目说明、履历事实：继续使用高可读中文字体，不强行 ASCII 化。
- 中文标题可以保留现有明确层级；若以后测试中文等宽字体，也只能替换短标题，不替换正文。

## 6. 页面分层

### Hero

- 主要信息仍是“UE / C++ 游戏开发”与中文说明。
- 背景可以出现低密度 ASCII 场；鼠标靠近时字符产生局部亮度与方向变化。
- 高功率蔓延只在一次启动事件或主 CTA 触发，不循环播放。

### GAME WORK

- 真实媒体全程保持清晰，不采样、不字符化，也不叠加长期 ASCII 滤镜。
- 项目切换使用干净的真实媒体交接；ASCII 只在共享窗口边框、状态轨、编号与邻近空白中传播。
- 字符信号必须与 active project 同步，并在媒体稳定后回到低密度安静状态。

### 栏目标题与阅读状态

- 不再使用静态像素材质带。
- 当前章节用一条 ASCII 字符进度场表示：稀疏字符缓慢填到密集字符，再稳定为一条低对比状态线。
- 标题、编号与说明仍是可读 DOM 文本，不能被 Canvas 替代。

### Archive / Profile / Contact

- 保持紧凑、招聘可扫描。
- ASCII 只用于行悬停、焦点反馈或小型状态图，不给每张卡片加独立动画。

## 7. CRT 外壳边界（第二轮）

第二轮才测试：

- 轻鱼眼：仅让装饰层和终端边界发生约 0.5%–1.5% 的桶形感，不扭曲正文坐标。
- 四角阴影：边角降低约 8%–14% 亮度，中央保持清晰。
- 扫描线：1px–2px、低于 6% 不透明度，不能压过中文细笔画。
- 磷光扩散：只对 ASCII 高亮字符，禁止全站模糊。

若真正的整页鱼眼需要 WebGL 重投影，优先放弃真实畸变，改用边框弧度、暗角和局部字符偏移模拟，避免破坏点击区域和文字清晰度。

## 8. 不变边界

- 不改项目事实、项目顺序、中文说明与链接。
- 不把任何游戏封面、项目截图、演示视频或 Sketchfab 内容转换成 ASCII；网站是 ASCII Terminal 风格，作品素材不是 ASCII 作品。
- 不把网站伪装成需要学习命令的操作系统。
- 不让 ASCII 背景拦截鼠标、键盘或滚动。
- 不用持续全屏 60 FPS 动画证明“高级”。
- 不在原型获批前直接替换已验收的 GAME WORK 切换。
